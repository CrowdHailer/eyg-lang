# Native Fetch

`src/http.zig` implements the `touch_grass/fetch` boundary from `next-tui`
`be502aa03df926a8f9df474a0a7fe16c8fb14fbd`.

```zig
pub fn effect(engine: *Engine, lift: Value) !Value;
pub const Response = struct {
    status: u16,
    headers: []const std.http.Header,
    body: []const u8,
};
pub fn get(allocator: Allocator, url: []const u8) !Response;
```

`effect` receives the actual EYG request record:

```eyg
perform Fetch({
  method: GET({}),
  scheme: HTTPS({}),
  host: "example.test",
  port: None({}),
  path: "/resource",
  query: Some("q=hello%20world"),
  headers: [{key: "Accept", value: "application/json"}],
  body: !string_to_binary(""),
})
```

It returns `Ok({status, headers, body})` or `Error(reason)`. `body` is a real
EYG binary; headers are a list of `{key, value}` records. HTTP 4xx/5xx statuses
remain successful HTTP responses. Reproducible closed-port, untrusted-certificate, hostname-mismatch, redirect-limit
and OPTIONS-body failures preserve the pinned Gleam `NetworkError("...")`
strings. Unmapped native failures retain explicit Zig error names. `get` exposes the same
transport to the read-only hub and returns caller-owned storage with normal Zig
error propagation.

The transport supports HTTP, verified HTTPS, optional ports/query strings,
UTF-8 URL text, binary request/response bodies, gzip/deflate decoding and up to
20 redirects. GET/HEAD ignore the supplied body, as in the reference transport.
POST 301/302 and non-GET/HEAD 303 redirects become GET; 307/308 replay the body.
Authorization, cookies and custom Host headers are removed when redirecting
across scheme, hostname or port. Header framing is generated by the transport;
provided Content-Length, Transfer-Encoding and Proxy-Authorization fields are
not forwarded as destination headers.

Behavior was checked against the actual pinned Gleam decoder, encoder and
`gleam/fetchx`, including its Bun runtime details: ordinary duplicate response
headers keep the last value, Set-Cookie fields remain separate at the end,
TRACE returns an empty body, and OPTIONS with a nonempty body returns an error.
Request header values follow Bun's accepted code points and wire encoding;
response header bytes decode as Latin-1. These observations avoid substituting
assumed browser semantics for the selected oracle.

## Failure compatibility

The failure oracle runs the actual `loam/system.run` and the platform's
`result.map_error(string.inspect)` conversion before `touch_grass/fetch.encode`.
Failure comparisons check complete Result values, including their strings.
`probe_errors.py` saves native/oracle values in `failure-probe.json`.

Some observed cases remain explicit compatibility gaps:

- Invalid headers and out-of-range ports throw JavaScript constructor exceptions
  outside the Result contract. Native Fetch returns an Error value.

The pinned Bun Request constructor recognizes a fixed set of methods; other
OTHER strings become GET. Native Fetch follows that behavior. A refused CONNECT
returns the proxy's HTTP response, including 407, without sending an origin
request or retrying over a direct or plaintext connection.

The report records each counterexample and sets `parity_complete: false` when
any remains. Diagnostic mappings cover the tested failure causes and first-hop
URLs; arbitrary platform/DNS errors and errors after cross-origin redirects are
not claimed to have identical JavaScript diagnostics. Working network behavior
is preserved rather than suppressing or disguising these failures.

## Libraries and review

The implementation reuses `std.http.Client`, `std.Uri`,
`std.crypto.Certificate.Bundle` and native `std.crypto.tls.Client`. It has no
OpenSSL, libcurl or C runtime dependency. HTTP extension methods longer than
std.http's eight-byte Method representation use a small request-line writer
while keeping the same acquired connection, HTTP response parser and TLS.

A review found that Zig 0.14.1's stock proxy CONNECT helper omits configured
proxy authentication and leaves the tunnel at the proxy's transport protocol.
The module therefore performs authenticated CONNECT explicitly and upgrades the
tunnel to TLS with the origin hostname and CA verification. A rejected proxy
request never triggers a direct-connection or plaintext HTTPS fallback.

Proxy configuration comes from `initDefaultProxies`, retaining the inherited
HTTP_PROXY/HTTPS_PROXY/all_proxy settings. Zig 0.14.1 has no NO_PROXY handling,
so exclusions are matched explicitly for every redirect hop. Exact hosts,
domain suffixes, optional ports, bracketed IPv6 exclusions and `*` are supported;
CIDR exclusions are not. Loopback is bypassed only when configured in NO_PROXY.
The process environment is never changed by the module.

On Android, TLS reads both `/apex/com.android.conscrypt/cacerts` and
`/system/etc/security/cacerts`. The directory loader accepts PEM and DER
certificates under hashed names such as `0123abcd.0`; missing platform
directories are skipped, and an empty trust bundle fails closed. Host tests
exercise PEM-only and DER-only stores through real verified local TLS.

TLS loads system trust and adds configured `SSL_CERT_FILE`, `SSL_CERT_DIR` and
`NODE_EXTRA_CA_CERTS`. Verification remains enabled. Standard-library limits
remain: IP-only subject alternative names and TLS nested through an
HTTPS-schemed proxy are unsupported. A conventional HTTP proxy carrying a
verified HTTPS origin is supported and tested.

Network scratch, connection and CA allocations use a temporary arena released
after each request. Returned bytes and header strings use the caller's allocator.
Responses are limited to 64 MiB, header storage to 64 KiB. I/O is synchronous;
network operations are not included in a universal 10 ms interaction guarantee.

## Reproduce

From the repository root, with Zig 0.14.1:

```sh
zig test packages/zig_runtime/src/http.zig
zig build-exe -O Debug --dep http \
  -Mroot=packages/zig_runtime/http/driver.zig \
  -Mhttp=packages/zig_runtime/src/http.zig -femit-bin=work/http-native
python3 packages/zig_runtime/http/verify.py
```

The verifier uses only loopback servers: HTTP, HTTPS and an authenticated local
CONNECT proxy that can reach only the local fixture origin. It preserves the
normal proxy environment except inside the explicit local-proxy test child.
Temporary test certificates are generated with Python `cryptography` under
`work/http-verification`; they are test fixtures, not application credentials.
The Gleam oracle needs the compiled pinned checkout and Bun from the main
oracle setup. `--skip-oracle` runs native protocol checks alone.

The suite checks all nine exposed method tags, a long OTHER method, binary and
Unicode data, header ordering/duplicates, gzip, redirects, credential stripping,
malformed input, CA and hostname rejection, authenticated TLS tunneling, proxy
refusal without fallback and the shared GET helper. It saves the explicit check
list and comparison count in `work/http-verification/result.json`.
