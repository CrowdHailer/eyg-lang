An agent should be able to discover its inputs as it works. Reproducibility comes from preserving what it observed—not from pretending a changing branch is a pure function.

1. A branch name is an observation

Suppose an agent asks for master, edits a file, and asks for master again. Meanwhile, somebody pushes a commit. A cache keyed only by repository URL and branch would give the agent stale files. Re-resolving the branch during replay would give it today's files. Neither reproduces the original execution.

The sandbox now records each acquisition as a separate external observation:

time 1  Acquire(repo, master) → commit A, artifact T₁
        another user pushes B
time 2  Acquire(repo, master) → commit B, artifact T₂

replay  Acquire(repo, master) → recorded A, stored T₁
        Acquire(repo, master) → recorded B, stored T₂

If the branch has not moved, both live lookups still happen. Their journal entries remain separate, while identical artifact blocks share a content identifier in storage.

Reproducible does not mean unchanging. It means we can reproduce the particular sequence of changes an execution observed.

2. Acquire an artifact; mount a workspace

The interface has two operations. Acquisition obtains immutable data and provenance. Mounting makes that data available at a new path in the private filesystem.

let receipt = match perform Acquire({
  source: Git({
    url: "https://example.com/team/project.git",
    ref: Some("master")
  }),
  expected: None({})
}) {
  Ok(receipt) -> { receipt }
  Error(reason) -> {
    let _ = perform StandardError(reason)
    !never(perform Exit(1))
  }
}

perform Mount({root: receipt.root, path: "repo"})

Replace the example URL with your repository. A successful acquisition returns Ok({root, resolved}). For Git, resolved is the full commit object ID. root is the EYG content identifier of the captured filesystem tree. ref: None({}) selects the remote's default HEAD; a branch, tag or commit can be supplied explicitly.

HTTP acquisition uses the same result and retention model:

perform Acquire({
  source: Http({url: "https://example.com/data.json"}),
  expected: None({})
})

Its artifact is a binary file, and resolved retains the requested URL. It is not a promise that the URL is immutable or an account of redirect destinations. Supply expected: Some(tree_or_blob_cid) to require an exact content identity. A mismatch returns an acquisition error. This field is an EYG artifact CID, not a Git commit hash or a raw file SHA-256.

Neither operation grants arbitrary process execution. Repository acquisition is expressed as Acquire followed by Mount; arbitrary Git commands are outside the EYG contract.

3. What happens during a live Git acquisition

  1. Decode the effect. touch_grass/acquire checks the source descriptor and optional expected CID. Overlay's acquire policy runs before the request reaches the broker.
  2. Apply the common broker rule. The broker fingerprints the complete acquisition input. A live Git request needs a Git authority: git:github.com, for example. An ordinary HTTP grant for github.com does not also grant Git acquisition.
  3. Allocate owned scratch space. The host uses an atomic temporary-directory operation. The agent cannot request that operation directly. The scratch path is neither mounted nor included in the receipt; adapter errors replace it with a placeholder.
  4. Fetch and resolve. Git clones into a fresh child directory with --no-checkout --no-local. It resolves the requested revision to a commit, then checks out that exact commit detached. For an unqualified name, the adapter tries the remote branch, then a tag, then the revision itself. refs/heads/… explicitly selects a remote branch.
  5. Capture the checkout. The fetcher reads regular files and directories, excluding .git. It rejects submodules, symbolic links and special files rather than manufacturing an incomplete representation. Git hooks are disabled for clone/checkout and core.autocrlf is set to false for checkout.
  6. Verify and clean up. The captured tree is stored by content. An expected CID is checked when present. The owned scratch directory is removed on the normal success and failure paths; cleanup failure is reported.
  7. Retain the result. The sandbox validates the bundle, registers its root and returns the receipt. Acquisition alone has not changed the workspace.

The native adapter returns the requested source, resolved commit and artifact bundle. The program receives the two identifying strings; the recording keeps the source descriptor and the artifact's complete block closure as well.

4. Request identity, Git identity, artifact identity

IdentityWhat it identifiesWhat it does not imply
Request fingerprintThe acquisition source and expected CID.That the same request always has the same answer.
Resolved Git commitThe commit selected by this particular fetch.That the remote will retain the objects forever.
Artifact root CIDThe actual captured files, recursively.That there is only one Git commit with those files.

The acquisition key is the CID of the canonical EYG-IR encoding of Acquire({source, expected}): a tagged value, encoded as DAG-JSON and hashed with SHA-256. The tag separates acquisition keys from ordinary HTTP request fingerprints. Record fields are sorted before encoding.

A file is stored as an EYG Binary module. A directory is a literal record from entry names to content references. Each directory therefore identifies its children transitively. These are EYG/DAG-JSON CIDs, not Git tree object IDs.

Two commits with different messages or parents may produce the same artifact root. Two identical acquisitions can therefore have different commit provenance while sharing the same file blocks. Conversely, the root identifies the actual captured checkout bytes, including the outcome of any applicable checkout transformations; it is not inferred from the commit string.

This is the part worth borrowing from Nix fetchers: turn external sources into immutable inputs. The extra requirement for agents is an ordered history of acquisitions, because an agent may intentionally observe the same mutable source more than once.

5. HTTP, models and acquisitions share one cursor

The broker does not maintain a separate Git cache or Git replay position. An agent session can contain:

0  model request             → model response
1  Acquire(repo, master)      → commit A, tree T₁
2  Fetch(status endpoint)    → "pending"
3  Acquire(repo, master)      → commit B, tree T₂
4  model request             → model response

The broker's state machine sees request keys and authorities. Its payload codecs distinguish HTTP responses, acquisition receipts and refusals, but ordering and permission decisions use one implementation:

Offline: refuse the external request and record the refusal.
Live:    check authority, invoke the adapter, append the observation.
Replay:  match the next key, consume its observation, return its payload.
Fork:    reuse the matching prefix; at the first mismatch,
         discard the old suffix and use permitted live requests.

The live adapter is a deferred callback. Replay never invokes it. There is no search through older entries for a matching request, and no automatic reuse of a previous live branch lookup. Repeated identical keys can appear at several positions with different payloads.

A replayed acquisition installs its stored artifact into the sandbox's retained-artifact store before resuming the program. Missing blocks, corrupt content, a different request, or unconsumed observations make replay fail. Successful acquisitions, adapter errors and broker refusals all have recorded outcomes.

For a changed prompt or policy, Fork preserves only the identical external prefix. Once execution diverges, even a later request that resembles an old request is live. This deliberately sacrifices speculative cache hits to avoid guessing which observation belongs to a new trajectory.

6. A second acquisition cannot overwrite private edits

Mount accepts only an artifact already retained in that environment. It resolves its destination inside the virtual filesystem, requires an existing parent, and refuses any destination that already exists—even an empty directory.

let request = {
  source: Git({url: "https://example.com/team/project.git", ref: Some("master")}),
  expected: None({})
}
let unwrap = (result) -> {
  match result {
    Ok(value) -> { value }
    Error(reason) -> {
      let _ = perform StandardError(reason)
      !never(perform Exit(1))
    }
  }
}

let first = unwrap(perform Acquire(request))
let _ = unwrap(perform Mount({root: first.root, path: "first"}))
let _ = perform WriteFile({
  path: "first/file.txt",
  contents: !string_to_binary("my private edit")
})

let second = unwrap(perform Acquire(request))
let conflict = perform Mount({root: second.root, path: "first"})
// conflict is Error: the private edit is still there.

let _ = unwrap(perform Mount({root: second.root, path: "second"}))
let _ = unwrap(perform Mount({root: first.root, path: "original"}))
{first, second, conflict}

first contains the agent's edit. second contains the second acquired version. original contains the untouched first version. The mounted filesystem is a persistent data structure: writing through one mount does not mutate the retained artifact or another mount.

To replace a workspace deliberately, delete its path and then mount the chosen root. The two steps are explicit; there is no hidden reset, pull, merge or staging-area behaviour. To reuse a known version, mount its retained root rather than acquiring a branch again.

Code dependencies are still pinned before each EYG run. If an agent wants to import EYG code from a newly acquired repository, it mounts the tree in one tool call and imports that code in a subsequent call. An import later in the same source block is still pinned before the block starts.

7. Start an agent without a project snapshot

eyg sandbox start prepares a configuration-only environment. It mounts the explicitly supplied configuration as /workspace/.overlay.eyg and pins its code dependencies. It does not copy the directory containing that configuration, inherit host environment variables, or provide an existing repository.

eyg sandbox start agent.eyg runs \
  "Acquire master from https://example.com/team/project.git and mount it at repo" \
  localhost git:example.com

The example assumes a local Ollama server and a repository you control; replace the URL and model name. localhost permits the model request. git:example.com permits the repository fetch. A local repository instead needs an exact grant such as git:file:/absolute/path/to/repository. Supported repository sources are HTTPS URLs and absolute local paths or local file:// URLs.

A self-contained agent.eyg configuration 
let pass = (request) -> { Pass(request) }
let deny = (_) -> { Mock(Error("unavailable")) }
{
  llm: {
    provider: Ollama({origin: "http://localhost:11434", api_key: None({})}),
    model: "qwen3"
  },
  policy: {
    acquire: pass, mount: pass,
    append_file: pass, create_key: deny, cwd: pass,
    delete_file: pass, env: (_) -> { Mock(None({})) },
    fetch: deny, make_directory: pass, now: pass,
    read_directory: pass, read_file: pass, sign: deny,
    sleep: pass, standard_error: pass, standard_in: deny,
    standard_out: pass, write_file: pass
  },
  context: {
    readme: "Acquire repositories, then mount their roots at new paths. Preserve existing edits."
  }
}

Both effect policy and broker authority must allow a live acquisition. Existing policies without acquire or mount keep those operations unavailable. The policy helpers' read_write grants mounting under selected roots but still denies acquisition until it is explicitly enabled.

8. The recording owns the data it needs

An acquisition receipt in the broker journal contains an actual content-reference edge to the artifact root. It is not merely a string containing a hash. Walking the journal's dependency graph therefore reaches the directory nodes and file blocks needed to reconstruct every acquisition.

The output environment also keeps a registry of retained artifact roots. An artifact survives environment export even when it was acquired but never mounted. Mounting a retained root in a later execution requires no external observation.

eyg sandbox replay runs/<id>.json
eyg sandbox export runs/<id>.json portable.json
eyg sandbox snapshot runs/<id>.json next-environment.json

# On another machine, with no repository or model server:
eyg sandbox replay portable.json

Local trace manifests share a content-addressed block directory. export collects a self-contained archive. Full sandbox replay reruns the configuration and tools, answers model/HTTP/acquisition requests from the ordered observations, and compares recorded EYG results, journals, terminal output and final environment identity. The older eyg replay command remains the narrower per-EYG-run journal verifier.

Preserving the commit is valuable provenance. Preserving the tree is what allows replay after the remote has been deleted.

9. Executable evidence

The real-Git integration program creates a temporary repository on master, commits file contents A, and lets an EYG program acquire it. Its trusted test adapter advances the repository to B before the identical second acquisition. The agent edits its first mount, gets an error when attempting to mount over it, and mounts the new version elsewhere.

The test compares the receipts with Git's actual commit IDs, exports and reloads the journal closure, deletes the source repository, and replays with a fetcher that panics if called. The values and final workspace must match.

# From packages/loam:
gleam run -m loam/runtime_acquire_integration \
  --target javascript --runtime bun

Additional tests cover mixed HTTP/acquisition ordering, unchanged branches resolving twice, artifact retention without mounting, exact expected-CID failures, authority refusal, scratch cleanup on Git failure, and an Overlay session starting from only its configuration before acquiring, exporting and replaying offline.

10. The guarantees have boundaries

  • Live acquisition needs a trusted adapter. Git must be installed for live repository acquisition. Host Git configuration and checkout filters can influence the initial captured bytes. The artifact CID identifies those actual bytes; replay does not run Git or its filters again.
  • The capture format is deliberately small. It represents regular files and directories, with normalised virtual permissions, not a Git working copy with an index and history. Symlinks, special files and submodules are rejected. Separate acquisition or additional format support is needed for those inputs.
  • Authorities are broker permissions. They constrain requested sources/endpoints. They are not operating-system network namespaces or per-redirect/per-socket enforcement.
  • Capture limits are not transport limits. Local/Git capture is bounded by 10,000 entries, 64 MB and 128 levels. Unique acquired payload bytes and logical mounted/written bytes have separate per-machine counters bounded by the write budget, initially 64 MB. These checks do not bound the size or duration of a native Git clone before capture.
  • Execution is bounded, not a native VM. Interpreter reduction and IO budgets remain in force. Hard JavaScript heap limits, preemptive worker isolation, bounded streaming transports and crash-safe incremental persistence are separate platform work.
  • Diagnostics are checkpoints. A hard sandbox stop preserves the latest completed agent trace, broker observations and final workspace. An in-flight tool's partial EYG journal may not have reached that checkpoint.

The invariant is simple: each live request observes the world once; the recording retains that observation and its immutable artifacts; replay follows the sequence without consulting the world again.
