# Aggregates

Historical study only: the [current constraints](README.md) supersede the local
database, snapshot and persistence proposals below.

Each aggregate is a consistency boundary with one event stream per instance. Proposed in round 3 by the owner of each context.

| Aggregate | Stream | Invariants | Emits | Proposed by |
| --- | --- | --- | --- | --- |
| WorkspaceConfiguration | `configuration/<workspace>` | SetWorkspaceSource is compare-and-set on expected_previous_cid; a stale base is rejected, never merged silently<br>the source block is stored before the event that references it<br>every change carries a reason; a revert carries restores=<earlier source CID> that exists in this stream<br>at most one version is in force; Applied only for a source CID in this stream and only the latest source (a superseded pending version is rejected)<br>a version that changes privilege is not applied without a PrivilegeChangeApproved reference<br>Applied lists the secret names read, the evaluated config CID and the package pins used to evaluate | WorkspaceCreated, WorkspaceSourceChanged, WorkspaceConfigurationApplied, WorkspaceConfigurationRejected | Avery |
| CheckpointChain | `evidence/checkpoints` | checkpoint positions strictly increase and each one commits to the previous checkpoint hash<br>the chain head hash equals the recomputed hash at that global position<br>signed only by the current key; a rotation is signed by the previous key<br>verification references an anchored checkpoint; a failed verification opens an incident that only TamperIncidentResolved closes<br>nothing in this stream is ever purged by retention | AuditLogCheckpointSigned, CheckpointAnchored, CheckpointKeyRotated, AuditLogVerified, AuditLogTamperDetected, TamperIncidentResolved | Avery |
| AuditExport | `evidence/exports/<export id>` | the scope is within the requester's audit grants<br>the export ends at an anchored checkpoint and includes raw events, upcaster CIDs and the checkpoint proofs<br>erased or purged payloads appear as tombstones, never as silent gaps<br>recipient and legal basis are mandatory | AuditTrailExported | Avery |
| UpcasterRegistry | `evidence/upcasters/<event type>` | one upcaster per (event type, from version)<br>the upcaster is a pure EYG function by CID and passes its test vectors<br>approved by a second person | EventUpcasterRegistered | Avery |
| RetentionSchedule | `records/retention/<workspace>` | a period is never below the statutory minimum for its category; evidence and decision envelopes are kept indefinitely<br>shortening a period needs an approval reference<br>a purge cites the policy version it applied, releases only payload roots older than the period, and never touches roots pinned by a hold | RetentionPolicySet, RetentionPurgeCompleted | Avery |
| LegalHold | `records/holds/<hold id>` | a hold has a matter, a non-empty scope and a placing person or the tamper policy<br>released at most once, by a different approver from the requester<br>a preservation hold opened by tamper detection cannot be released while its incident is open | LegalHoldPlaced, LegalHoldReleased | Avery |
| DataSubject | `records/subjects/<subject id>` | each request has a received time and a deadline<br>the key is shredded at most once per key version<br>a shred requires the active-holds view at a global position no earlier than the request; if a hold is placed afterwards, it lands on already-shredded data and the conflict is reported, not hidden (the cross-aggregate race is accepted and made visible)<br>a refusal names the holds that block it | ErasureRequested, ErasureRefusedUnderLegalHold, SubjectKeyShredded | Avery |
| Run | `runs/<run_id>, where run_id is derived from the cause: turn = conversation + turn number, trigger = hash(definition CID, event id), occurrence = hash(schedule id, due instant), child = hash(parent run, step), invocation = message id` | appends are conditional on the expected version; that conditional append is the fence, and the lease only avoids wasted work<br>RunBasisPinned comes before the first effect decision, and replay never consults the hub or the current configuration for anything already recorded<br>steps are contiguous; every EffectPassed is followed by exactly one of EffectResultRecorded, EffectFailed or EffectOutcomeInDoubt before the next decision<br>buffered local results are flushed (LocalEffectResultsRecorded) before any EffectPassed of an effect that is visible outside the run or changes state<br>an unsafe effect is never performed twice without an EffectReconciled that says retry<br>replay must request the same effect label and input digest as recorded at each step, otherwise ReplayDiverged and the run fails<br>nothing is appended after RunCompleted, RunFailed or RunCancelled<br>EffectMocked results are never emitted as EffectResultRecorded | RunStarted, RunBasisPinned, EffectInputRewrittenByGate, EffectPassed, EffectMocked, EffectDenied, GateFailed, EffectResultRecorded, LocalEffectResultsRecorded, EffectFailed, EffectRetryScheduled, EffectOutcomeInDoubt, EffectReconciled, RunSuspended, ChildRunAwaited, RunResumed, RunResumedUnderNewShell, ReplayDiverged, RunCheckpointed, RunCompleted, RunFailed, RunCancelled | Rui |
| RunLease | `fleet/leases/<run_id> (in the lease store, coordination not evidence)` | at most one holder at a time<br>the epoch increases on every acquisition<br>an acquisition only follows a release or an expiry<br>only a machine that has joined and is not draining can acquire | RunLeaseAcquired, RunLeaseReleased, RunLeaseExpired | Rui |
| Machine | `fleet/machines/<machine_id>` | a draining machine takes no new leases<br>MachineDrained only after all its leases are released or expired | MachineJoined, MachineDrained | Rui |
| Admission | `fleet/admission/<workspace>` | live runs do not exceed the workspace limit or any channel's limit<br>a sequential child uses its parent's slot<br>queued runs are admitted in priority order and never dropped<br>Delegate depth is at most 4 | RunThrottled | Rui |
| ScheduleBook | `schedules/<workspace>/<conversation> and schedules/<workspace>/configured` | names are unique per book, and setting an existing name replaces it (recorded on the new event)<br>each occurrence id (schedule id + due instant) fires at most once<br>a cancelled schedule never fires<br>a reminder fires once and is then done<br>missed occurrences follow the schedule's declared catch up policy (default: one late fire, the rest CronOccurrenceMissed) | ReminderSet, RecurringScheduleSet, ScheduleOccurrenceFired, CronOccurrenceMissed, ScheduleCancelled | Rui |
| ChannelTriggers | `triggers/<workspace>/<channel>` | runtime trigger names are unique per channel<br>a configured trigger wins a name clash, and the runtime one is shadowed, not deleted<br>a stopped, shadowed or deleted trigger matches nothing<br>adding the same name with the same definition CID is a no-op, and with a different definition it needs ReplaceTrigger<br>each (definition CID, event id) produces at most one TriggerMatched | TriggerAdded, TriggerReplaced, TriggerSavedToWorkspace, TriggerShadowedByConfiguration, TriggerMatched, TriggerScriptFailed, TriggerStopped, TriggerResumed, TriggerDeleted | Rui |
| CloudInstallation | `identity/cloud` | bootstrapped exactly once<br>the bootstrap code is single use and expires<br>nobody can sign up before bootstrap | CloudBootstrapped | Sam |
| Person | `identity/person/<person id>` | one Person per verified provider and subject<br>sign-up only from an unexpired, unused invitation<br>a deactivated person cannot sign in or be re-invited without a new PersonInvited<br>personal fields are encrypted with the subject key, the id is pseudonymous | PersonInvited, PersonSignedUp, PersonSignedIn, SignInRejected, PersonDeactivated | Sam |
| SignInGuard | `identity/signin/<provider>/<subject digest>` | rejections for unknown subjects are recorded and rate limited<br>the subject is stored as a keyed digest, not as raw text | SignInRejected | Sam |
| Credential | `identity/credential/<credential id>` | the value is shown once and stored only as a hash<br>has an expiry<br>its shell is no wider than the issuer's at issue time<br>revoked is final<br>compared in constant time | ApiCredentialIssued, CredentialRevoked | Sam |
| ShellCatalog | `access/shells` | shell names are unique<br>each published definition names its cloud.eyg source CID and shell CID<br>a widening definition references an approved PrivilegeChange | ShellDefinitionPublished | Sam |
| ChannelAccess | `access/channel/<workspace>/<channel>` | exactly one channel shell CID in force<br>every change names the WorkspaceConfigurationApplied it came from<br>a widening change references an approved PrivilegeChange | ChannelShellChanged | Sam |
| PrivilegeChange | `access/proposal/<proposal id>` | decided at most once: approved, declined or expired<br>the approver is a person acting directly, freshly authenticated, and is neither the proposer nor the person the proposer acted for<br>approval is refused if the target's version moved past the expected version<br>self-approval only with a sole admin and after 24 hours, flagged | PrivilegeChangeProposed, PrivilegeChangeApproved, PrivilegeChangeDeclined, PrivilegeChangeExpired | Sam |
| PersonGrants | `access/person/<person id>` | at least one active admin in the cloud (checked against an admin count, refused otherwise)<br>the assigned shell exists in ShellCatalog<br>widening grants reference an approved PrivilegeChange<br>binding is allowed only if the person's shell has a bind gate that passes for that channel<br>no grants or bindings for a deactivated person | AdminGranted, AdminRevoked, PersonShellAssigned, PersonBoundToChannel, PersonUnboundFromChannel | Sam |
| SecretVault | `secrets/<workspace>` | names are unique<br>versions increase by one<br>no value, plain hash or handle in any event, only name, version and HMAC fingerprint<br>SetSecret, RotateSecret and DeleteSecret need a person as the acting principal<br>a deleted name is not reused without a new SecretSet at a new version | SecretSet, SecretRotated, SecretDeleted | Sam |
| SecretEgress | `secrets/egress/<run id>` | each injection references an EffectPassed step of the same run<br>the host is in the secret version's allowed hosts at that moment<br>only explicit handles are injected (except deprecated bearer secrets, recorded as implicit)<br>at most one injection record per step and secret, so replays do not double count | SecretInjectedIntoRequest, SecretInjectionRefused | Sam |
| LeakRegister | `secrets/leaks/<workspace>` | records the secret name, version, where it was found (event type, run and step or message) and the redaction, never the matched text<br>every redaction opens a rotation proposal | SecretLeakRedacted | Sam |
| TrustStore | `packages/trust/<workspace>` | a key fingerprint is trusted at most once per name scope<br>trusting needs an approved PrivilegeChange, revoking needs none<br>revocation records compromised-since and is final<br>every change bumps the trust store version that verifications cite | SignatoryTrusted, SignatoryRevoked | Sam |
| PackageRelease | `packages/release/<package name> (mirror of the hub)` | a version names exactly one CID<br>versions are monotonic<br>signed by a key that was valid in the signatory chain at signing<br>retraction never deletes the CID | ModulePublished, ReleaseSigned, ReleaseRetracted | Sam |
| ReleaseVerification | `packages/verification/<workspace>/<release CID>` | verification hashes the fetched bytes and compares them to the CID before checking the signature<br>cites the trust store version it used<br>a verification invalidated by SignatoryRevoked is never reused | PackageSignatureVerified, PackageVerificationFailed | Sam |
| WorkspacePins | `packages/pins/<workspace>` | one pin per package name<br>only releases with a valid PackageSignatureVerified under the current trust store can be pinned<br>pinning a retracted release needs an explicit confirmation | PackagePinned | Sam |
| Channel | `channels/<workspace>/<platform>:<channel_id>` | A platform message id is recorded at most once (redeliveries are deduplicated)<br>A reaction or retraction refers to a message already recorded, or carries the full message as the plugin reports it<br>Messages from Self participants are recorded, never queued for an agent<br>MessagePosted refers to the run and step whose Post produced it, and to the platform's message id<br>The current name is the latest ChannelNamed. Config is resolved from the name in force when a message arrives | MessageReceived, ReactionAdded, MessageRetractedOnPlatform, MessagePosted, ChannelNamed, ChannelHistoryOpened | Priya |
| Conversation | `conversations/<workspace>/<platform>:<channel_id>:<thread>` | At most one agent turn in progress<br>Inputs start turns in the order they were queued<br>Each turn is exactly one run, and AgentTurnCompleted closes it<br>ConversationRestarted increments the epoch, and results for an older epoch are discarded<br>Every turn ends in exactly one of MessagePosted (via its run) or AgentStayedQuiet | InputQueued, AgentTurnStarted, AgentRanProgram, SubagentDelegated, AgentStayedQuiet, AgentTurnCompleted, ConversationRestarted | Priya |
| Connection | `connections/<workspace>/<connection_name>` | The name is unique in its workspace<br>A webhook with no secret exists only after an attributed UnauthenticatedConnectionCreated<br>Backfill happens once per connect, and its events are not live<br>The poll cursor only moves forward<br>No deliveries are accepted after ServiceDisconnected until it is connected again | ChatConnected, ServiceConnected, UnauthenticatedConnectionCreated, ConnectionBackfilled, PollCursorAdvanced, ServiceDisconnected | Priya |
| DeliveryInbox | `deliveries/<workspace>/<connection_name>/<yyyy-mm-dd>` | A delivery id or source event id is recorded once within the replay window (WebhookReplayDetected otherwise)<br>A signature is verified before WebhookDeliveryAuthenticated<br>Credential headers and query parameters never reach the event, and bodies are blocks by CID<br>ConnectionEventReceived is live only when the Connection is not backfilling | WebhookDeliveryAuthenticated, WebhookDeliveryRejected, WebhookReplayDetected, ConnectionEventReceived | Priya |
| Artifact | `artifacts/<workspace>/<name>` | The owner channel is fixed by the first save<br>Only the owner channel shares, unshares or changes visibility<br>A non-owner channel saves only while the artifact is shared for editing<br>Versions are numbered 1, 2, 3 with no gaps, and each is an immutable root CID<br>A bundle has valid paths and media types before a version is saved<br>Names are unique per workspace (today they are global across the cloud) | ArtifactVersionSaved, ArtifactSharedForEditing, ArtifactUnsharedForEditing, ArtifactVisibilityChanged | Priya |
| ContentScope | `content/<workspace>\|content/public` | a root is pinned only once every block under it is present and verifies against its CID<br>only the holder that pinned a root (hold id, tag, operator) can release it<br>pins and sweeps are serialized in this stream: a sweep records its mark epoch, and any root pinned or referenced after the epoch is excluded from that sweep<br>a block younger than the grace period (24h) is never swept, which protects blocks written before their event is appended<br>at most one sweep in progress per scope<br>blocks of the public scope are never swept while any release references them | ContentRootPinned, ContentRootReleased, GarbageCollectionSweepCompleted, BlockIntegrityFailed, BlockRepaired | Dana |
| Projection | `projections/<read model>` | one rebuild at a time per read model<br>a rebuild records the projector CID and the global position or snapshot it started from<br>the read model only serves queries once caught up to the position recorded at rebuild start | ProjectionRebuilt | Dana |
| FileSystem | `files/<workspace>` | every change names expected previous_root, which must equal the head, otherwise the command is retried against the new head (the paths do not conflict) or rejected<br>paths are normalized and absolute, and the root cannot be deleted<br>file bytes are put as chunked blocks (256 KiB) before the event is appended; the event holds only CIDs<br>a change made by a run commits in the same ledger append as that run's EffectResultRecorded (internal effect, exactly-once)<br>restore targets must be roots that are still live (in LiveRoots) | FileWritten, DirectoryCreated, FileDeleted, FileRestored, FileSystemSnapshotTagged, FileSystemRestored | Dana |
| Database | `databases/<workspace>/<name>` | single writer; statements apply in stream order, and the stream version equals the outbox sequence<br>(run, step) is unique, so a retried write is a no-op<br>only deterministic statements are accepted<br>raw statements require a shell with with_databases; dataclip statements carry the dataclip CID<br>a snapshot names the sequence it covers and its logical digest<br>a restore names its snapshot and sequence, and every statement after it applies to that base | DatabaseStatementExecuted, DatabaseSnapshotTaken, DatabaseRestored | Dana |
| Dataclip | `dataclips/<workspace>/<name>` | the invoked version is the dataclip CID in the configuration applied at invocation<br>a dataclip runs with its own shell, recorded on the event, not the caller's<br>a read-only dataclip emits no DatabaseStatementExecuted | DataclipInvoked | Dana |
| CloudConfiguration | `configuration/cloud` | source changes are compare and set on the previous source CID<br>adding or widening a catalogue shell needs a second person (A4) | CloudSourceChanged | Avery, Sam (sign off, N1) |
