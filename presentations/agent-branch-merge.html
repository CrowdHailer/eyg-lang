The branch joins two bodies of work: a hosted agent system and a broader roadmap of runtime, tooling, query and native implementation work. The organizing principle is the repository's existing goal: stronger guarantees through explicit constraints, particularly at the point where a program requests an effect.

The rewrite reduced 101 original commits to 89. Repeated design changes and integration repairs were folded into the relevant introductions. Cloud dependencies and a deployable checkpoint now come first. The four slices in this presentation are a proposed review and landing strategy, not four existing PRs. Read the staged history rather than attempting to review the entire diff as one feature.

All evidence is a snapshot of the reviewed branch on 13 November 2026. Existing green checks must be rerun on the eventual merge candidate. Source links use the reviewed commit wherever possible.

Read: cloud model and effects · channel plugin contract02

A plugin preserves its native message value and publishes an EYG input type. Each configured channel supplies a pure handle function checked against that type. Its work requests select sessions, observations, invocations, posts and triggers. Conversation history is retained; program lexical scope is not. The model's ordinary reply is not automatically posted: the agent must run an EYG program that performs Post. This makes speaking to the channel an explicit, controllable effect too.

A channel shell is a complete record of effect gates, type checked whenever it is set. Missing fields are configuration errors. Start from cloud.reject_all, then override selected gates. A gate can pass or modify a request, mock a result, or explicitly reject the effect. Workspace configuration is trusted EYG and is reevaluated for turns, triggers and direct invocations. This gives live configuration changes a well-defined entry point.

The review should follow reset and queue behavior through asynchronous execution, then verify that direct code blocks, triggers and delegates cannot bypass the shell. The example chat uses howdy and Lustre live components, with browser checks for composition, threads and reactions. Session tests cover selected sessions, resets, policy-controlled posts and agent imports.

Evidence: failed-policy-write regression · trigger events · tracing03

Script and agent imports are introduced only after session filesystems. They read through the session ReadFile gate, including nested, deferred, redirected and mocked imports; a trusted configuration root never grants scripts host filesystem access.

This stage turns a chat demo into a workspace that can respond to events and keep useful state. The breadth of integrations is less important than the repeated contract: each connection converts external activity into channel events, and the resulting program still runs through its channel policy.

A concrete bug exposed the importance of transactional thinking. Updating a user's shell could change the in-memory registry even when writing the user configuration failed. The corrected order persists successfully before activating the new shell. The regression checks that the old policy remains active after a failed write.

Artifact validation was consolidated with the hub instead of maintaining a cloud copy. The original history also changed server implementation later; the rewritten history introduces the final server dependency with the first artifact server. This makes review about capability growth rather than temporary infrastructure choices.

For merge review, concentrate on ownership, path boundaries, the lifecycle of secrets, and the relationship between a logged policy decision and the operation actually performed. A shared gate is only as effective as each host adapter's enforcement.

Hardest problem / preserve set semantics

An empty record is still one fact.

"$unit" INTEGER UNIQUE DEFAULT 0

Seed and deduplicate the same unit value.

Merge review: check table semantics, SQL seeding and rule scheduling together.
Read: SQL planner regressions · cloud database tests · dataclips04

Cloud databases were originally near the end of the combined branch, but a coherent cloud checkpoint needs them. They rely on typed tables in the IR, parser, analysis and evaluator, plus the compiler's SQLite planner and shared SQLite effect definitions. Those are genuine dependencies, so they move forward with the cloud feature.

The rewrite introduces the final indexed evaluator and the planner for evaluated query tables directly. It avoids asking reviewers to approve an earlier SQL compilation design and then its replacement. Query awareness is added to later serializers, native tool adapters and compiled execution when those components are introduced.

The zero-column relation is the useful edge case: the empty record is a value, so a set containing it has one member. SQL needs a representation that preserves that identity. A unique unit column and consistent seeding restore set behavior; this fixes a particular duplicate-driven nontermination case, not every possible recursive query termination problem.

Review this as one semantic boundary spanning language values, the SQL representation and the cloud scheduler. Check that dataclip authority is explicit and that local host support is not accidentally required by the early cloud checkpoint.

Read: compiled modules · shallow handlers · tracing06

The branch's second major stage is execution infrastructure. A bounded interpreter returns control after a finite reduction slice and can resume later. Retained shells carry typed cells and state forward. Shallow handlers and masks add scope-sensitive behavior. Tracing and recorded effects must follow the same lifecycle, including cancellation and suspension.

The integration difficulty is that query callbacks and profiling add their own return contexts. They cannot bypass the continuation machinery. The compiled path therefore invokes query callbacks through its trampoline, and query builtins are included in both ordinary program output and ES-module output. A regression exercises an exported compiled query; the generated runtime was refreshed when the host API was introduced.

Validation from the branch review includes 49 compiler tests plus 138 spec fixtures and 97 JavaScript interpreter tests. Soundness search later generates typed programs and exposed duplicate record-label validation needs. These checks support semantic review, but do not replace reading the handler and continuation transitions.

Related CLI improvements preserve subsequent stdin bytes, edit prompts by grapheme, stop recorded turns safely and cache verified package responses. They fit this stage because they make retained execution usable without damaging its inputs or history.

Portable trajectories contain enough pinned program and effect history to inspect and verify a session. Secret redaction and verified acquisition are part of the format's usefulness, not optional presentation features. The shared portable SHA-256 implementation was introduced with the first trajectory work so later provider transports reuse it.

Artifact workspaces add isolated previews, reusable typed viewers, revision history, import/export and sharing. Host integrations include TodoMVC, Hashi and nginx, Raspberry Pi boot support, and terminal components. These examples exercise the host API rather than each inventing an independent execution model.

Pi and OpenCode bring a specific authority problem: policy on the EYG tool is insufficient if the surrounding harness still offers equivalent unrestricted native tools. Shared native tool policies and the OpenCode dispatcher make this an integration question that can be tested through the actual upstream path.

Branch validation included real browser artifact workflows, offline agent evaluations and an upstream OpenCode dispatcher run. Cloud-wide trajectory recording, shared policy libraries and offline evaluation of recorded cloud events remain integration opportunities described in the roadmap note; do not infer that every cloud turn is already exported as a trajectory.

Read: authorization tutorial · proof trees · channel-policy prototype08

This stage should not be presented as a second query engine. The language and planner support already arrived before the cloud checkpoint. Later commits implement local SQLite effects, add a large movie-data example, document query model trade-offs, cover essay examples and integrate highlighting. Authorization examples then use these ordinary typed query values to express roles, delegation and agent permissions.

Proof trees return facts, derivations and successful guards behind answers. They are explanations of evaluation, not cryptographic attestations of fact origin. The host must own trusted identity and lifecycle facts, apply tenant and resource boundaries, and enforce the decision when performing an effect.

The channel-policy package demonstrates Slack-channel-based page access and GitHub PR authorization with mocked integrations. The cloud already has Slack and GitHub connections, so connecting the prototype to live channel triggers is a plausible next step, but it is not completed merely by having both pieces in this branch.

Review policy fixtures and failure cases alongside the documentation. Keep claims about query purity separate from claims about computational cost or termination: a well-typed pure recursive query can still be expensive or non-terminating.

Evidence limit: this branch review reran native unit tests and a release smoke test. It did not rerun the full differential campaigns or assemble an Android APK.
Merge decision: accept an explicitly experimental package, or land it separately after refreshed parity and device evidence.
Read: runtime scope and oracle · Android build blocker · saved reports09

The native package is a large independent addition, not a prerequisite for the cloud or the JavaScript/BEAM toolchain. It targets Zig 0.14.1 and compares against a pinned Gleam implementation on next-tui. Its own fixtures deliberately match that oracle rather than claiming all current root-spec features.

The hard part of native optimization is making a correctness and latency claim refer to the same executable and workload. The package records seeds and reduced counterexamples, compares terminal buffers after individual events, and separates dispatch/frame timings from physical key latency. The documented Escape ambiguity timer alone rules out a universal sub-10 ms key latency claim.

The prior branch review built and tested the native runtime and checked a simple release evaluation. Full differential campaigns and benchmark reproduction were not repeated as part of that review. Existing reports should be treated as versioned evidence to inspect and reproduce for any release claim.

The Android documentation records successful native cross-compilation but an APK assembly blocker fetching the React Native Android artifact from repo.reactnative.dev. No APK or device launch is claimed. Decide whether this package lands as explicitly experimental or moves to a separately gated PR; either choice should preserve its documented compatibility limits.
